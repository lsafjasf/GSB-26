# maxflow — 最大流 / 最小割库（Python 3，仅标准库）

## 文件

| 文件 | 说明 |
|---|---|
| `maxflow.py` | 库本体：Dinic + 推送-重标号两种算法，统一接口 `make_maxflow`，输出最大流值、最小割边集合、各边流量 |
| `bruteforce.py` | 参考实现：Ford-Fulkerson 暴力增广（仅用于对拍） |
| `stress_test.py` | 对拍脚本：随机小图上三种实现的流值/割容量必须一致 |
| `test_degenerate.py` | 退化与边界用例集（unittest） |
| `benchmark.py` | Dinic 单算法耗时测试（稀疏 / 稠密 / 二分匹配 / 分层） |
| `benchmark_compare.py` | 两种算法在稠密 / 随机稀疏 / 分层对抗网络上的耗时与相位数/迭代次数对比（含对拍） |
| `example.py` | 用法示例 |

## 统一接口与算法选择

```python
from maxflow import make_maxflow, ALGORITHMS   # ALGORITHMS = ("dinic", "push_relabel")

mf = make_maxflow(n, algorithm="push_relabel")  # 或 "dinic"（默认）
mf.add_edge(u, v, cap)
value = mf.max_flow(s, t)
cut_value, cut_edges, S = mf.min_cut(s, t)
print(mf.stats)   # dinic: {"phases": ...}  push_relabel: {"pushes": ..., "relabels": ...}
```

两种算法共用同一残量图结构，`max_flow` 后均可取最小割与各边流量，
结果一致（对拍保证，见下）。

## 算法与复杂度

| 算法 | 实现 | 复杂度 |
|---|---|---|
| Dinic | BFS 分层 + DFS 阻塞流（当前弧优化） | 一般图 O(V²·E)；单位容量 / 二分匹配 O(E·√V) |
| 推送-重标号 | highest-label 选择 + gap 启发式 + 当前弧 | O(V²·√E) |

实现要点：
- **反平行边**：每条原始边独立建一对残量边，u→v 与 v→u 互不干扰。
- **自环 / 零容量边**：允许存在，分层图中不会被使用，不影响结果。
- **超大容量**：Python int 任意精度，内部 INF 取所有容量之和（有限整数），
  已验证 2×10¹⁸ 无溢出。
- **s == t**：按约定返回流值 0 与空割。
- **最小割**：最大流后在残量网络上从 s 沿正残量边可达的点集为 S，
  割边集合 = 所有 S→T 的原始正容量边；割容量 = 最大流值（对偶性，
  对拍与单测中强制校验）。

### 结论：什么输入用哪个算法

- **稠密图选推送-重标号**：稠密图上 Dinic 的 DFS 阻塞流在巨大邻接表上
  反复扫描，而推送-重标号的操作数（推送 ~V·√E 量级）增长更慢，
  n=1,200 时快约 1.8 倍，且优势随密度扩大。
- **随机稀疏大图选 Dinic**：稀疏图上相位数极少（4–5 轮 BFS），
  Dinic 每相是连续的 BFS/DFS，常数远小于推送-重标号的逐点
  discharge（10 万点时推送 127 万次、重标号 104 万次），Dinic 快约 2.6 倍。
- **分层对抗网络选 Dinic**：层间全连接使一个相位的阻塞流即达到最大流
  （相位数=1），是 Dinic 的最有利结构；推送-重标号仍需逐点把盈余
  推回/推前，慢 5–7 倍但增长平稳、无退化风险。
- 没有单一算法在所有输入上最优：Dinic 的耗时随相位数波动，
  推送-重标号的耗时随推送/重标号次数平稳增长，可按上表经验选择。

## Dinic 单算法耗时数据（Python 3.12，单次最优值）

稀疏网络（E ≈ 4V）：

| V | E | 耗时 |
|---|---|---|
| 10,000 | 39,994 | 71 ms |
| 50,000 | 199,994 | 1.29 s |
| 100,000 | 399,996 | 2.64 s |

稠密网络（E ≈ 0.5·V²）：

| V | E | 耗时 |
|---|---|---|
| 300 | 44,670 | 55 ms |
| 700 | 244,600 | 536 ms |
| 1,200 | 719,366 | 1.98 s |

完全稠密（E = V(V−1)）：n=200 → 32 ms；n=400 → 247 ms。

二分匹配（单位容量，p=q=5000，E≈110k）：217 ms，匹配值 5000。

分层对抗网络（L=10, 宽=200，E=360k）：559 ms。

结论：随机稠密图上 Dinic 实际表现远优于 O(V²E) 上界（分层轮数极少）；
稀疏大图瓶颈在建图与 BFS，10 万点 / 40 万边约 2.6 s。

## 对拍说明

`stress_test.py` 每轮生成 n∈[2,8]、m∈[0,3n] 的随机图（含自环、反平行边、
15% 零容量边、偶发 10¹² 大容量），对 Dinic / 推送-重标号 / 暴力增广
三种实现校验：

1. 三种实现的最大流值一致；
2. 三者最小割容量一致，且各自等于流值；
3. 割边集合合法（全部 S→T，容量和 = 流值）；
4. 两种高效实现的流满足容量约束与流量守恒。

默认 20,000 轮全部通过。
