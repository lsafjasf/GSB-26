# 吞吐与延迟数据

环境：Python 3.12.3 / Linux，仅标准库。机器线程数 ≥ 8；数值为 `python3 bench.py 200000 8`
单次运行结果（每次运行末尾断言 `global total == 所有线程本地写入总数`，无丢失/重复）。
完整原始输出见 `bench_output.txt`。

## 本地写热路径（不合并且无读者）

| 场景 | 吞吐 |
|---|---|
| 单线程纯本地 add | ~5.6M adds/s |
| 单线程 add（含并发读者，close 时一次合并） | ~3.1M adds/s |
| 8 线程 add（无中途 flush） | ~4.4M adds/s 合计 |

本地写不触碰任何共享锁；合并是 O(批内不同 key 数) 的批量应用
（swap-out 为 O(1)：整个 delta dict 换出），例如 200 万次单 key 写入的
一次性合并约 0.03 ms。

## 不同 flush 频率 / 线程数（含 2 个持续读线程）

| 线程 | flush 周期 | 合计吞吐 | flush p50 / p99 | 全局快照读 p50 / p99 |
|---|---|---|---|---|
| 1 | 1000 | ~2.5M/s | 1.3µs / 8.1µs | 0.3µs / 0.7µs |
| 2 | 1000 | ~3.8M/s | 1.0µs / 6.9µs | 0.3µs / 0.7µs |
| 4 | 100 | ~4.4M/s | 0.75µs / 3.7µs | 0.3µs / 0.6µs |
| 8 | 1000 | ~4.4M/s | 1.0µs / 6.0µs | 0.3µs / 0.7µs |
| 8 | 100 | ~4.1M/s | 0.75µs / 3.6µs | 0.3µs / 0.7µs |

说明：
- 全局读 p50 稳定在 ~300ns（持锁拷贝 dict），与线程数基本无关。
- flush 为小批量（每 ~1000 次写一次）时 p99 为几 µs；大批量合并耗时随
  批内不同 key 数线性增长，摊到每次本地 add 仍然极低。
- 压测中 2 个读线程是无 sleep 死循环抢占 GIL/全局锁，因此尾延迟偶发被
  调度放大到 ms 级（见 max 列）；p50/p99 不受影响。生产中读者不会这样
  空转，尾延迟会明显更好。
- 所有并发场景下，读者观察到的 (视图, 总量) 始终自洽（原子读），总量
  单调不减，最终精确等于写入总数。
