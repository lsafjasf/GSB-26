# refcount — 引用计数与弱引用管理库（Python 3，仅标准库）

## 文件
- `refcount.py` — 库：强引用 `Managed`、弱引用 `WeakRef`、环检测 `find_cycles()`、回收 `collect()`
- `test_refcount.py` — 单元测试 + 并发不变量测试（17 个用例）
- `bench.py` — 百万次增减引用性能 + 泄漏检查

## 运行
```bash
python3 test_refcount.py -v   # 全部测试
python3 bench.py              # 性能与泄漏数据
```

## 销毁时机与回调顺序
- 强计数在 `release()` 内降为 0 时**同步销毁**（确定性析构），并级联释放子对象。
- 级联用显式栈迭代实现，长链（10k+）不爆递归栈。
- 回调顺序：父对象回调先于子对象回调；同一对象内按注册顺序；回调执行时弱引用已失效。

## 环检测与回收
- `find_cycles()`：Tarjan SCC，报告每个环涉及的对象及 `reclaimable` 标志；
  仍被外部根持有的环标记为不可回收并报告涉及对象。
- `collect()`：从根（自动推断：强计数 > 图内入度）做可达性遍历，
  不可达对象（含环）先断开内部边再逐个销毁，回调与弱引用失效照常触发。

## 并发不变量（测试断言）
- I1: `strong_count >= 0` 恒成立（不漂移）
- I2: 持有强引用期间对象必定存活（不提前销毁）
- I3: 销毁后 `WeakRef.get()` 必为 `None`（不悬空）

## 实测数据（Python 3.12，本机）
- 单线程 retain+release ×1,000,000：0.226s（≈4.4 M ops/s）
- 8 线程 retain+release ×1,000,000：0.234s，计数无漂移
- create+destroy ×1,000,000：0.546s
- 泄漏检查：10 万对象 + 1 万环 + 10 万弱引用后存活数回到基准，无泄漏
