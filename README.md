# SECDED 纠错码库（扩展汉明码，纯标准库 Python 3）

在不可靠存储/传输上提供**单比特纠错（SEC）+ 双比特检测（DED）**。
核心原则：检测到的不可纠错误一律拒绝输出，绝不当作已纠正放行，避免污染数据。

## 文件

- `secded.py` —— 库：`encode/decode`（整数位运算快速实现）+ `ref_encode/ref_decode`（逐位穷举参考实现）
- `test_diff.py` —— 对拍脚本：两套实现在单比特全位置 + 三比特全组合 + 随机多比特翻转下结论必须一致
- `bench.py` —— 编码开销表 + 吞吐基准

## 运行命令

```bash
python3 test_diff.py     # 对拍自测（约 266 万次译码比对，约 1 分钟）
python3 bench.py         # 开销表 + 吞吐基准（约 15 秒）
python3 bench.py --quick # 快速版基准
```

## 用法

```python
from secded import encode, decode, CORRECTED, NO_ERROR, UNCORRECTABLE

cw = encode(0b10110101, k=8)        # 8 位数据 -> 13 位码字
res = decode(cw ^ (1 << 5), k=8)    # 翻转比特 5
assert res.status == CORRECTED and res.error_position == 5
assert res.data == 0b10110101
```

`decode` 返回 `DecodeResult(status, data, error_position)`，三态结论：

| status | 含义 | data |
|---|---|---|
| `no_error` | 无错 | 原始数据 |
| `corrected` | 单比特错已纠正，`error_position` 给出码字比特位置（0 = 整体校验位） | 纠正后的数据 |
| `uncorrectable` | 检测到不可纠错误（≥2 比特），**拒绝输出** | `None` |

## 码结构与校验位/校正子推导

数据位宽 `k` 可配置。取满足 `2^r >= k + r + 1` 的最小 `r` 作为汉明校验位数，
码字总长 `n = k + r + 1`：

- 比特 `1..m`（`m = k + r`）：经典汉明码。位置 1, 2, 4, 8, …（2 的幂）放校验位，其余按序放数据位。
- 比特 `0`：整体奇偶校验位（比特 1..m 的偶校验）。

**校验位**：把位置编号写成二进制，位置 `j` 属于第 `i` 个校验组当且仅当 `j` 的第 `i` 位为 1。
第 `i` 个校验位（位于 `2^i`）= 其校验组内所有比特的异或，使每组异或和为 0。

**校正子**：译码时重算各组异或和，拼成 `s`。若仅位置 `e` 翻转，则第 `i` 组异或和翻转
当且仅当 `e` 的第 `i` 位为 1 —— 故 **`s` 的二进制值就是出错位置**，`s = 0` 表示汉明部分无错。
整体校验 `c`（全码字异或）对任意奇数个错误翻转。判决表：

| 校正子 s | 整体校验 c | 结论 |
|---|---|---|
| = 0 | 0 | 无错 |
| 1 ≤ s ≤ m | 1 | 单比特错，位置 = s，翻转即纠正 |
| = 0 | 1 | 整体校验位自身出错（位置 0），翻转即纠正 |
| > m | 1 | 缩短码未使用的校正子（≥3 比特错），不可纠，**拒绝输出** |
| ≠ 0 | 0 | 偶数个错误（≥2），不可纠，拒绝输出 |

整体校验位把最小汉明距离从 3 提升到 4，因此可"纠 1 检 2"。
注意：≥3 比特的错误仍可能被误纠或漏检，这是 SECDED 的固有限制；
但缩短码未使用的校正子取值（s > m）一定判 `uncorrectable`，绝不当作合法位置翻转。
对拍脚本要求两套实现结论一致，并强制验证：双比特错必判 `uncorrectable`，
三比特翻转下凡标注 `corrected` 的结果必须位置合法且重新校验通过。

## 编码开销 vs 理论下界

单比特纠错的理论下界是 Hamming 界：`2^r >= k + r + 1`，即 `r` 个校验位。
本实现用 `r + 1` 个校验位，**只比下界多 1 位**——这位就是整体奇偶校验位，
用来换取双比特检测能力（dmin 3 → 4）。另外当 `k + r + 1` 不是 2 的幂时，
存在未使用的校正子取值（表中"未用校正子"列），这是汉明码按 2 的幂取整的固有零散。

实测（`python3 bench.py`，CPython 3.12）：

| 16 | 5 | 1 | 22 | 6 | 27.27% |
| 32 | 6 | 1 | 39 | 7 | 17.95% |
| 64 | 7 | 1 | 72 | 8 | 11.11% |

纠错路径与无错路径吞吐几乎相同（纠错只是多一次位翻转），
说明瓶颈在校正子计算而非纠正逻辑；按比特计的吞吐随 k 近似线性增长。

## 位宽选型建议

- **k = 64（72 位码字）**：通用推荐。开销 11%，单块正好覆盖一个机器字，
  解码约 24 万块/秒（≈17 Mbit/s 有效数据）。
- **k = 32 或 8/16**：小报文、按字节寻址的场景；开销较大（18%–38%），
  但单块出错损失的数据少。
- **k ≥ 256**：开销 < 4%、比特吞吐最高，适合顺序读写的块设备/文件存储；
  代价是一次不可纠错误丢弃整块，且块越大块内出现 ≥2 比特错的概率越高。
- 经验法则：块误码率 ≈ `C(n,2)·p²`（p 为比特错误率）须远低于可接受的丢块率；
  若物理通道错误率较高，选更小的 k 以控制块内多比特错误概率，而不是追求低开销。

## 对拍测试覆盖

`test_diff.py` 对 15 种位宽（k = 1…128，含非 2 幂如 26、57、120）：
全零、全一、1 组随机数据 ×（无错 + 全部 n 个单比特翻转位置 + **全部 C(n,3) 种三比特翻转**
+ 100 组随机 2–6 比特翻转），共约 266 万次译码比对。
参考实现与快速实现逻辑独立：`ref_decode` 不用校正子定位，而是在距离 ≤1 的
候选中**搜索最近合法码字**（用 `ref_encode` 重编码验证），n ≤ 22 时三比特翻转
逐组合对拍，更大 n 抽样对拍。
并额外断言：单比特错必纠正且位置正确、双比特错必判不可纠、
三比特翻转下凡标注 `corrected` 的结果必须位置合法（`0 <= pos < n`）且
纠正后的码字重新校验通过（重编码比对 + 再次译码为 `no_error`）。
