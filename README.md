# Skip List（Python 3，仅标准库）

有序索引跳表：支持并发读 / 单写者、范围扫描、可复现的随机层数。

## 文件

| 文件 | 说明 |
|---|---|
| `skiplist.py` | 库：`get` / `insert` / `delete` / `scan` / `search_steps` |
| `test_skiplist.py` | 正确性、边界（空表/单元素/重复键/极端层数）、可复现性 |
| `test_concurrent.py` | 多读者 + 单写者并发测试 |
| `test_memory.py` | 10 万次插入删除后的节点回收证据 |
| `bench_steps.py` | 查找步数实测 vs 期望、层数概率 p 对内存的影响 |

## 运行命令

```bash
python3 -m unittest test_skiplist -v     # 正确性 / 边界 / 可复现性
python3 -m unittest test_concurrent -v   # 并发（每个用例约 2 秒）
python3 -m unittest test_memory -v -s    # 内存回收（-s 显示证据输出）
python3 bench_steps.py                   # 步数与内存数据
```

## 设计要点

**可复现层数**：随机源通过构造函数注入（`SkipList(rand=random.Random(seed).random)`）。
相同种子 + 相同操作序列 ⇒ 节点层数序列完全一致（`test_same_seed_same_level_sequence`、
`test_level_draws_match_random_stream`）。

**并发模型**：写者持锁串行化；读者无锁。节点先完整构造好出边，再用单次前驱指针
赋值发布；删除只摆动前驱指针、从不动被删节点自身的 `next`，因此正在遍历该节点的
读者仍能沿着有效链继续走 —— 不会读到半更新节点（CPython 引用赋值原子）。

**范围扫描**：沿第 0 层单向迭代。扫描期间的插入/删除不会跳过"扫描全程都在表中"
的键（`test_scan_never_skips_stable_keys`），也不会重复返回同一记录（前向单调）。

**节点回收**：删除即解除链接，CPython 引用计数立即回收（循环引用由 gc 兜底）。
`test_memory.py` 的证据：10 万次插入+删除循环后，`_Node` 实例数从峰值回落到
仅剩头节点（before=0 → after=1），WeakSet 中 10 万个曾被跟踪的节点存活数为 0，
tracemalloc 稳态后增长 < 1 KB。

## 步数与内存（n=50,000，5,000 次随机查找）

步数统一按指针读取计数：每次沿当前层前进算一步；每次降层后读取该层前向指针也算一步。

| p | 实测步数（水平跳+降层） | 期望 (1/p)·log_{1/p}(n) | 实测/期望 | 指针槽/节点 | 理论 1/(1-p) | 节点内存 |
|---|---|---|---|---|---|
| 0.10 | 39.1 | 47.0 | 0.83 | 1.11 | 1.11 | 6.8 MB |
| 0.25 | 31.6 | 31.2 | 1.01 | 1.33 | 1.33 | 6.9 MB |
| 0.50 | 29.8 | 31.2 | 0.96 | 2.00 | 2.00 | 7.2 MB |
| 0.75 | 47.2 | 50.1 | 0.94 | 3.98 | 4.00 | 8.0 MB |

- 统一口径后，实测步数是该渐近估计的 0.83–1.01 倍；此前 p=0.5 看似只有约一半，是因为漏计了每次降层后的指针读取，并非公式存在约三倍偏差。
- p≈0.5 附近水平遍历与降层的综合步数较优；p 升高时层数更多，降层读取也随之增加。
- 内存随 p 单调上升：每节点期望指针数为 1/(1-p)，p 从 0.1 → 0.75 时指针槽从
  1.11 → 3.98，与理论值精确吻合。层数概率越高，跳得越快但每节点越贵。

## 边界覆盖

空表、单元素、5000 次重复键插入（覆盖写、不产生新节点）、全部一层
（退化为有序链表，查找线性）、全部最高层 —— 见 `test_skiplist.py`。
