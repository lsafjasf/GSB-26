# 最大流算法库（Python 3，仅标准库）

Dinic 最大流 + 最小割实现，含暴力对拍、随机对拍、退化用例集与性能基准。
容量使用 Python 任意精度整数，**不会溢出**。

## 目录结构

```
maxflow/
  dinic.py          核心库：Dinic（BFS 分层 + 当前弧阻塞流，迭代式 DFS）
  brute.py          对拍参考：Ford-Fulkerson 增广 + 枚举全部源汇割
tests/
  crosscheck.py     随机对拍：流值一致性 + 流割恒等 + 小图枚举割 + 流守恒
  test_degenerate.py 退化/边界用例集（19 个用例，含当前弧对抗网络回归）
  benchmark.py      稀疏 / 稠密 / 超大容量 / 分层对抗网络耗时基准
run_all.sh          一键跑全部测试与基准
```

## 算法与复杂度

- **算法**：Dinic。每个相位先 BFS 构造分层图（只走残量为正、层数严格 +1 的弧），
  再用**当前弧优化**的 DFS 反复增广得到阻塞流；相位最多 O(V) 个。
  当前弧游标只在该弧被确认无法再贡献流量（推送后饱和，或弧头在当前分层图中
  已是死路）时才前移——**不能在一次成功推送后就前移**：该弧可能仍有残量、
  下游仍可达 t，同一相位必须能反复利用它。游标提前前移会让每个相位只推出
  一条增广路，相位数随增广次数增长（稀疏对抗网络上实测可达数千个相位），
  不再是阻塞流、O(V²E) 分析也随之失效。
- **时间复杂度**：一般网络 **O(V²E)**；单位容量网络 O(E·min(E^(1/2), V^(2/3)))。
  阻塞流阶段每相位 O(E)（当前弧：每条弧每相位至多被扫过一次）。
  增广次数与容量数值大小**无关**（不同于朴素 Ford-Fulkerson 的 O(E·|f|)），
  因此容量差异极大（10^200 量级）也不会卡住。
- **空间复杂度**：O(V + E)（邻接表 + 正向弧/反向残量弧成对存储）。
- **正确性要点**：
  - 每条输入边插入一对弧：正向弧容量 c、反向残量弧容量 0。增广时同时
    `fwd.cap -= d, rev.cap += d`，天然支持反平行边（每条边独立成对，互不抵消）
    与“退流”。
  - 阻塞流后残量网络中从 s 可达集记为 S。最后一次 BFS 时 t 不可达，
    故不存在 S→T 的残量正弧；割只由饱和的原始边构成，
    由最大流最小割定理，流值 = 割容量。
- **实现细节**：DFS 用显式栈（`maxflow/dinic.py` 的 `_augment`），
  图很大时不受 Python 递归深度限制；推送后沿栈回溯弹出已饱和的弧，
  第一个仍有残量的弧保留在栈顶且游标不动（下一次直接复用）；
  到达死路时标记 `level[u]=-1` 并回溯，由父顶点将对应弧判废、前移游标，
  与递归当前弧写法等价。`MaxFlow.phase_count` 记录上次求解的 BFS 相位数
  （供基准与回归测试使用）。

## 退化输入处理

| 情形 | 处理方式 |
|---|---|
| 反平行边 | 每条边独立插入正/反弧对，容量不抵消（对拍覆盖） |
| 自环 u→u | 对 s-t 流与 s-t 割无贡献，记录边 id 但不插入残量网络，`flow_on` 返回 0 |
| 零容量边 | 正向弧残量为 0 永不增广；若跨最小割则仍出现在割边集合中（容量贡献 0） |
| 源点出边容量为 0 | 与其他出边共存，正常处理（退化用例覆盖） |
| 超大容量 / 容量差极大 | Python 大整数精确运算，无溢出；增广次数不依赖容量量级 |
| 源汇相同 s==t | 按定义流值 0、割为空集 |
| 无路径 | 流值 0，割为可达侧 S 到 T 的原始边（可能为空，容量 0） |
| 重边 | 容量独立累加，割中分别列出 |
| 非法输入 | 顶点越界、容量为负/浮点、负顶点数等抛出明确异常 |

## 实测耗时

环境：Python 3.12.3，AMD Ryzen 7 9700X，WSL2（Linux 6.18，x86_64）。
每组重复求解 3 次（重新建图），下表为最短耗时；基准用随机种子 42 生成。

| 网络 | 顶点 V | 边 E | 建图 | 求解 |
|---|---:|---:|---:|---:|
| 稀疏随机有向图（平均出度≈4） | 20,000 | 79,993 | 117 ms | **390 ms** |
| 稠密随机有向图（p=0.10） | 1,000 | 99,877 | 141 ms | **200 ms** |
| 超大容量稀疏图（容量 10²–10²⁰⁰） | 5,000 | 19,994 | 23 ms | **2,639 ms** |

以上为**修复前**（游标提前前移的错误写法）同一次运行 3 次重复中的最短耗时；
随机器负载有波动（种子 42 可复现网络结构）。

观察：

- 修复前稀疏/超大容量组的相位虚高（13 / 727 个），耗时被成倍放大；
  超大容量组看起来的“大整数开销”实际主要是额外相位的重复扫描。
- 快速小规模基准：`python3 tests/benchmark.py --quick`（秒级）。

### 当前弧修复前后对比（同一台机器、同一网络、最短耗时）

分层对抗网络：容量为 k 的宽走廊 `0->1->...->k`，末端扇出 k 条
单位容量车道 `w->v_j->t`。正确写法 1 个相位推完全部 k 单位阻塞流；
错误写法退化成每相位 1 条增广路、共 k 个相位。

| 网络（k=3,000，V=6,002，E=9,000） | 相位数 | 求解耗时 |
|---|---:|---:|
| 修复前（游标成功推送即前移） | **3,000** | **3,968 ms** |
| 修复后（确认无法再贡献才前移） | **1** | **1,228 ms** |

快速档（k=400，V=802，E=1,200）：修复前 400 相位 / 62.3 ms，
修复后 1 相位 / 20.0 ms。

### 修复后实测（同环境，3 次重复取最短）

| 网络 | 顶点 V | 边 E | 相位数 | 建图 | 求解 |
|---|---:|---:|---:|---:|---:|
| 稀疏随机有向图（平均出度≈4） | 20,000 | 79,993 | 4 | 105 ms | **88 ms** |
| 分层对抗网络（宽走廊+单位车道） | 6,002 | 9,000 | 1 | 8 ms | **1,228 ms** |
| 稠密随机有向图（p=0.10） | 1,000 | 99,877 | 4 | 140 ms | **67 ms** |
| 超大容量稀疏图（容量 10²–10²⁰⁰） | 5,000 | 19,994 | 20 | 19 ms | **86 ms** |

观察：

- 各网络相位数均为个位数到几十（分层对抗网络恒为 1），符合 O(V) 界，
  不再随增广次数增长。
- 超大容量组修复后仅 86 ms：额外开销与容量量级无关，此前的 2.6 s
  几乎全部来自游标 bug 造成的 727 个虚高相位。
- 分层对抗网络修复后仍需约 1.2 s，这是 Python 迭代式阻塞流本身
  O(k²) 次弧扫描（每次增广都要重走宽走廊并更新残量）的固有成本，
  而非相位问题；正确性不受影响，C 扩展/递归写法可进一步优化常数。

## 对拍

- `tests/crosscheck.py`：默认 2000 组（含零容量边、10^30/10^100 超大容量、
  反平行边、自环），每组校验：
  1. Dinic 流值 == 暴力 Ford-Fulkerson 流值；
  2. 返回割的容量 == 流值（流割恒等）；
  3. V≤12 时与**枚举全部源汇分离割**的最小容量完全相等；
  4. 容量约束与所有中间点流守恒、源汇净流量等于流值。
- `tests/test_degenerate.py`：16 个固定退化用例，含源汇相同、无路径、
- `tests/test_degenerate.py`：19 个固定退化用例，含源汇相同、无路径、
  单边、完全二分 K_{3,3}（超级源/汇，流值受供给=需求=14 限制）、
  10^200 容量差、经典需“退流”网络、非法输入，以及两个当前弧优化
  回归用例（宽走廊+单位车道分层对抗网络：必须 1 个相位推完；
  双瓶颈共享宽弧：同样必须 1 个相位）。

## 库 API

```python
from maxflow.dinic import MaxFlow, max_flow

mf = MaxFlow(n)
e0 = mf.add_edge(0, 1, 10**100)   # 容量为非负整数；返回边 id
value = mf.max_flow(s, t)         # 流值（任意精度 int）
cut = mf.min_cut()                # [Edge(id, u, v, capacity), ...] 割边
assert mf.cut_capacity(cut) == value
f = mf.flow_on(e0)                # 单条边上的净流量

# 一步求解
result = max_flow(n, [(u, v, c), ...], s, t)
result.value, result.cut, result.cut_capacity
```
