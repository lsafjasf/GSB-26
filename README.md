# sensfind：敏感数据发现库

Python 3 实现，仅使用标准库。从文本中识别身份证号、银行卡号、手机号，
输出命中位置、类型、置信度与判定理由；被校验否定的候选可追溯否定原因。

## 文件结构

- `sensfind/detectors.py` — 三类检测器（正则初筛 + 校验复核）
- `sensfind/engine.py` — 归一化、阈值过滤、重叠冲突消解
- `sensfind/__main__.py` — 命令行入口
- `scripts/gen_dataset.py` — 构造评测数据集（种子固定，可复现）
- `scripts/run_eval.py` — 评测：混淆矩阵、误报率/漏报率、阈值多档扫描、
  冲突消解记录、吞吐；输出 `REPORT.md` 与 `eval_out/` 下逐样本/逐条记录
- `tests/selftest.py` — 边界情形、功能与评测指标口径自测
- `data/dataset.jsonl` — 550 条构造样本（330 正例 / 220 负样本）
- `REPORT.md` — 评测结果（混淆矩阵、误报率/漏报率、阈值扫描、消解记录、吞吐）
- `eval_out/per_sample.jsonl` — 每个阈值档下逐样本结论（tp/fp/fn 明细，可 diff 比对）
- `eval_out/conflicts.jsonl` — 规则重叠命中的逐条消解记录

## 判定依据

### 身份证号（id_card）
1. 正则初筛：18 位，末位数字或 X。
2. 校验位：GB 11643-1999 加权求和（硬校验，失败即否定）。
3. 前缀：前 2 位省级行政区划代码必须在有效表中（硬校验）。
4. 日期：出生日期必须合法且年份在 1900 至今之间（硬校验）。
5. 置信度：基础 0.50 + 校验位 0.25 + 区划 0.10 + 日期 0.10 + 上下文 ±。

### 银行卡号（bank_card）
1. 正则初筛：13–19 位数字，允许空格/短横线/换行作为分组分隔符。
2. 校验位：Luhn 算法（硬校验）。
3. 前缀：IIN/BIN 必须命中已知发卡组织表（62 银联、4 Visa、51–55 MasterCard 等，硬校验）。
4. 合理性：全部数字相同直接否定；16–19 位常见长度加分。
5. 置信度：基础 0.45 + Luhn 0.25 + IIN 0.15 + 常见长度 0.05 + 上下文 ±。

### 手机号（mobile）
1. 正则初筛：1 开头 11 位，允许空格/短横线/换行分隔。
2. 前缀：第二位必须在 3–9（号段硬校验，如 123/110 开头被否定）。
3. 合理性：连续升降序序列（如 13456789012）否定；数字重复度过高降权。
4. 置信度：基础 0.50 + 号段 0.15 + 数字分布 0.10 + 上下文 ±。

### 上下文与阈值
命中点前后各 16 字符内出现正向关键词（身份证/卡号/手机等）加分，
出现负向关键词（订单/编号/工单/快递等）降分。置信度低于阈值（默认 0.6）
的候选被过滤，并在 `rejected` 中记录 `stage=threshold` 及原因。

## 规则冲突消解

同一串数字可能同时命中多类模式（如 62 开头的 18 位身份证同时满足银行卡
Luhn + IIN）。消解规则是确定性的，依次比较：

1. 置信度高者优先；
2. 并列时跨度长者优先；
3. 再并列时类型优先级 `id_card > bank_card > mobile`；
4. 再并列时起始位置靠前者优先。

被弃候选与胜出候选都记录在 `result.conflicts` 中（含该规则文本）。
实现上先按位置扫描出重叠连通分量（O(n log n)），分量内按上述优先级贪心选取。

## 运行命令

```bash
python3 scripts/gen_dataset.py     # 重新生成数据集 data/dataset.jsonl
python3 tests/selftest.py          # 自测（空文本/超大文本/换行分隔/零宽字符等）
python3 scripts/run_eval.py        # 评测并生成 REPORT.md 与 eval_out/
python3 scripts/run_eval.py --compare 0.6 0.4   # 逐样本比对两个阈值档的结论
echo "联系电话：13812345678" | python3 -m sensfind            # 扫描 stdin
python3 -m sensfind 文件路径 --threshold 0.7                  # 扫描文件
```

## 评测指标口径

所有指标由 `scripts/run_eval.py` 从 `data/dataset.jsonl` 重算，可复现：

- TP/FP/FN 为实体级计数（按 gold value 匹配）；
- TN 为样本×类型级计数（某样本某类型既无 gold 也无预测时记 1）；
- 误报率 FPR = FP / (FP + TN)；漏报率 FNR = FN / (TP + FN) = 1 - Recall；
- 阈值多档扫描每档均给出误报率与漏报率；每档逐样本结论写入
  `eval_out/per_sample.jsonl`（按 threshold、id 排序），阈值调整后同一批
  样本的结论可用 diff 逐条比对，或用 `--compare` 直接查看差异。

## 边界情形覆盖

- 空文本 / 纯空白：直接返回空结果；
- 超大文本：自测含 5MB 级文本，吞吐见 `REPORT.md`（混合文本约 3 MB/s）；
- 换行与分隔符：卡号/手机号支持空格、短横线、换行分组；
- 编码异常字符：零宽字符（U+200B/200C/200D/FEFF）归一化时剔除，
  命中位置仍映射回原文偏移；孤立代理项等异常字符不会导致崩溃。

## 评测结果摘要（详见 REPORT.md）

阈值 0.6 时构造数据集上 micro Precision/Recall/F1 均为 1.0，误报率与漏报率
均为 0；阈值降到 0.40 时负向上下文样本泄漏（FP=10，误报率 0.0076），
升到 0.80 以上漏报率上升（0.90 时漏报率 0.2424）。注意：数据集为
构造数据，与规则同源，衡量的是规则一致性与边界行为，不代表真实文本上的
表现；真实场景应在此基础上用抽样人工标注数据重新标定阈值。
