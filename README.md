# GSB-26：DFS 图遍历缺陷修复

Python 3，仅标准库。

## 文件

| 文件 | 说明 |
| --- | --- |
| `dfs.py` | 修复后的迭代 DFS（`Graph` / `DFSWalker` / `Edge` / `WalkResult`） |
| `buggy_dfs.py` | 修复前的缺陷实现（两类常见错误写法），仅用于复现 |
| `test_dfs.py` | 4 个缺陷复现用例 + 12 个修复回归/不变量/顺序规则用例（含十万节点链） |
| `verify.py` | 可复跑验证：顺序规则 vs 实际输出逐条核对 + 可复现性哈希 + 耗时/内存 |
| `benchmark.py` | 百万节点 / 千万边性能与内存基准 |

## 四类缺陷与修复

1. **超深链栈溢出**：缺陷版 `_visit` 递归调用，链深超过 ~1000 即 `RecursionError`。
   修复：显式栈 + 邻接边迭代器（`stack: list[Iterator[Edge]]`），零递归，
   栈深最坏等于图深度而非调用栈深度。测试在 `sys.setrecursionlimit(200)`
   下完整遍历十万节点链。
2. **环上节点重复访问**：缺陷版“离开节点时才标记”，环路上节点未标记被反复进入。
   修复：**发现（入栈）即标记**（gray-marking），任一节点最多入栈一次，
   `on_node` 对每个可达节点恰好触发一次。
3. **无向/并行边重复处理**：无向边在两端邻接表各存一份，缺陷版处理两次。
   修复：无向图用 `seen_edges` 按 `edge_id` 去重，每条边恰好处理一次；
   并行边 edge_id 不同，各自恰好处理一次。有向图边只存一份，
   不建 `seen_edges`（千万边规模省 ~400 MB）。
4. **异常路径状态污染**：缺陷版 `visited` 是实例属性且跨 `walk` 复用，
   异常后残留，再次遍历丢节点。修复：遍历状态全部为 `walk()` 内的临时变量，
   `try/finally` 保证异常时清空并复位遍历器；异常后再次遍历与全新遍历
   的节点序列、边序列逐元素一致。

## 稳定遍历顺序规则（同图同配置完全可复现）

- **邻接边排序**：每个节点的邻接边按 **(终点, edge_id) 升序** 排列，
  与 `add_edge` 调用先后无关（懒排序：首次访问邻接表时一次性排序并缓存，
  `add_edge` 保持 O(1)）。约束：同一邻接表内的终点之间、edge_id 之间
  必须可相互比较（推荐统一用 int 或 str）。
- **节点序**：先序 DFS。起点最先访问；处理边 (u,v) 时若 v 未发现则立即
  深入 v，v 的全部邻接边先于 u 的后续邻接边处理；回溯时继续。
- **边序**：边在首次被看到时触发 `on_edge`（去重后）；节点在发现时
  触发 `on_node`。
- 相同输入 ⇒ 多次遍历、跨进程遍历结果完全一致（`verify.py` 用
  SHA-256 指纹验证，指纹跨进程复跑可逐字符比对）。

## 去重策略（重复边 / 自环）

- **edge_id 全局唯一**：`add_edge` 重复使用已有 edge_id 直接抛
  `ValueError`（fail-fast），保证“边身份 == edge_id”无歧义。
- **并行边**（同端点、不同 edge_id）：全部保留，各自恰好处理一次
  （多重图语义），邻接表内按 edge_id 决定相对顺序。
- **自环 (u,u)**：有向图存一份、处理一次；无向图同样只存一份
  （不生成反向副本）、处理一次。
- **无向非自环边**：两端邻接表各存一份，遍历时按 edge_id 去重，
  全图恰好处理一次。

## 性能与内存实测

环境：Python 3.12.3，Linux，16 核 x86_64，15 GiB 内存；图为有向多重图
（主干 i→i+1 保证全可达 + LCG 确定性随机边，seed=20260926）。
`benchmark.py` 遍历使用回调计数、不保存节点/边序列
（`track_nodes/edges=False`，生产常态）；计时为预热 2 轮后 3 轮中位数，
RSS 取自 `/proc/self/statm`，遍历峰值由 10 ms 采样线程测得。

**1,000,000 节点 / 10,000,000 边（有向图）**

| 指标 | 实测值 |
| --- | --- |
| 建图耗时 | 26.8 s（含 edge_id 唯一性登记） |
| 遍历耗时（中位数） | 8.37 s（单轮 8.37 / 7.36 / 8.69 s） |
| 遍历吞吐 | ~1.20M 边/秒（~0.84 µs/边） |
| 图占用 RSS | 2318 MB（约 232 B/边，含节点表与 edge_id 集合） |
| 遍历额外峰值 RSS | +81 MB（visited 集合 + 显式栈） |
| 遍历结束后残留增量 | ≈ 0 MB（状态在 finally 中释放） |
| 结果断言 | 访问节点 1,000,000；处理边 10,000,000；`completed=True` |

**100,000 节点深链（verify.py，跟踪完整序列）**：遍历 0.061 s，
节点序逐条 == 0..99,999，边序逐条 == 0..99,998，额外 RSS 6.9 MB。

**小档 100,000 节点 / 1,000,000 边**：建图 1.5 s，遍历 0.58 s
（~1.72M 边/秒），图占 239 MB。

说明：以上为 CPython 解释执行、且每条边执行一次 Python 回调的口径；
`verify.py` 大档因保存完整节点/边序列做逐条核对，吞吐口径
（0.94M 边/s）低于 `benchmark.py` 的纯计数口径（1.20M 边/s）。
内存大头是图本身（每边 `Edge` namedtuple + list 槽位 + edge_id 集合），
遍历算法自身在百万节点/千万边下额外峰值仅约 81 MB（纯计数口径）。
