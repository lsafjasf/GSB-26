# 冷热分层内存存储（TieredStore）

纯 Python 3 标准库实现：热数据留内存、冷数据下沉磁盘文件，读路径对上层透明。

## 文件

- `tiered_store.py` — 库源码
- `test_tiered_store.py` — 自测（对拍测试 + 边界情形）
- `experiments.py` — 策略对比 / 预取效果 / 热点收敛实验
- `experiment_results.txt` — 实验输出存档

## 运行命令

```bash
python3 test_tiered_store.py   # 14 个测试：对拍 + 边界
python3 experiments.py         # 3 组实验，打印命中率/延迟/磁盘 IO/收敛时间
```

## 设计

**冷热判定依据**（权重均可配置）：

```
score(key) = freq_weight * freq(key) + recency_weight / (1 + age(key))
```

- `freq`：访问频次，每 `decay_interval` 次访问整体乘以 `decay_factor`（指数衰减），
  突发热点几次访问即可抬升 score，过气热点随时间冷却；
- `age`：距上次访问的 tick 数，即最近访问时间项。

**迁移时机**：

- 下沉（热→冷）：写入后热层字节数超容量，按 score 最低者逐个淘汰落盘；
  开 `early_sink` 后，每次写入额外把 score 低于 `sink_score_threshold` 的数据提前下沉。
- 上浮（冷→热）：读命中冷层立即上浮（可能连锁触发下沉）；
  开 `prefetch` 后，顺带把 key 排序相邻的 `prefetch_count` 条冷数据一起上浮。
- 单条数据大于热层容量时直接落盘、读时不上浮，保证容量极小时依然正确。

**可配置参数**：`capacity_bytes`、`freq_weight`、`recency_weight`、`decay_interval`、
`decay_factor`、`prefetch`、`prefetch_count`、`early_sink`、`sink_score_threshold`。

## 实验数据（本机实测，详见 experiment_results.txt）

**实验 1：淘汰策略对比**（Zipf 负载，3000 key × 256B，热层 64KB ≈ 8.5%）

| 策略 | 热层命中率 | 平均读延迟 | 磁盘读 | 磁盘写 |
|---|---|---|---|---|
| LRU（仅最近时间） | 80.05% | 13.9us | 5984 | 5984 |
| LFU（仅频次） | 82.28% | 12.6us | 5316 | 5316 |
| 组合（默认） | 82.28% | 12.1us | 5316 | 5316 |
| 组合+预取 | 82.34% | 98.6us | 26481 | 26481 |
| 组合+提前下沉 | 82.26% | 11.6us | 5321 | 5067 |

结论：倾斜负载下频次项优于纯 LRU；预取在随机负载下磁盘读放大 ~5 倍、命中率几乎无收益，应只对顺序负载开启；提前下沉用少量磁盘写换内存余量。

**实验 2：预取开关**（顺序扫描 2000 key × 3 遍，热层 51KB ≈ 10%）

| 配置 | 热层命中率 | 平均读延迟 | 磁盘读 |
|---|---|---|---|
| 预取关 | 0.00% | 59.9us | 6000 |
| 预取开（8条/次） | 17.95% | 529.0us | 44199 |

结论：顺序扫描是 LRU 类策略的最坏情况（0% 命中）；预取把命中率拉到 18%，
但容量远小于数据集时预取数据在被读到前又被挤出，磁盘读放大明显——预取收益依赖"热层容量 ≥ 预取窗口"。

**实验 3：突发热点收敛**（旧热点 A 400 key 消亡 → 注入新热点 B 50 key 占 80% 访问）

| 策略 | 收敛读次数 | 收敛耗时 | 热点命中率（尾段） |
|---|---|---|---|
| LRU | 247 | 6.3ms | 100% |
| LFU 无衰减 | 1943 | 99.0ms | 100% |
| LFU 衰减 | 247 | 7.1ms | 100% |
| 组合 | 247 | 6.6ms | 100% |

结论：读触发上浮使各策略都能在 ~250 次热点访问内识别新热点；
但旧热点占满热层时，无衰减的纯 LFU 被历史频次"压死"，收敛慢 7.9 倍——频次衰减是快速收敛的关键。

## 正确性保障

- 对拍测试（`DuelTest`）：5 组随机种子 × 数千次随机 get/put/delete，
  每次 get 与纯内存 dict 参照比对，结束后全量比对所有 key 的值；
  覆盖默认/LRU/LFU/预取+提前下沉/超小容量五种配置。
- 边界情形：空存储、单条数据、容量小于单条数据（直接落盘）、容量为 0（全部数据冷）、
  覆盖冷层旧值、读后上浮与连锁淘汰、突发热点驻留。
- 频次表有界：读不存在的键只计 `misses`，不更新频次表、不推进访问时钟，
  因此百万级无效查询不会让频次结构增长（规模只与真实 key 数有关），也不会
  因 miss 推进 tick 触发衰减而抹掉真实热点频次（百万次 miss 回归用例）。
